## Быстрый старт

### За один шаг

```sh
make demo
```

Эта цель поднимает PostgreSQL в Docker, создаёт `.venv`, ставит
зависимости, накатывает все SQL-скрипты и запускает приложение.
Окно «Авторизация» откроется через несколько секунд — войдите как
`admin / admin`.

### По шагам

```sh
make db-up         # 1. Поднять PostgreSQL 17 в Docker
make venv          # 2. Создать виртуальное окружение
make install       # 3. Установить Python-зависимости
make db-init       # 4. Применить миграции и базовый seed
make run           # 5. Запустить десктопное приложение
```

### Требования к системе

- macOS 12+, Linux x86_64 или Windows 10/11.
- Docker Desktop / Docker Engine (для PostgreSQL).
- Python 3.10+ (`brew install python@3.12` на macOS).
- На Apple Silicon: Makefile сам определяет архитектуру и подставляет
  `arch -arm64` для всех Python-вызовов.
- Для сборки РПЗ: `pandoc` + `npx` (mermaid-cli ставится автоматом).

Все цели документированы; полный список:

### Окружение

| `make bootstrap`     | поднять БД + создать venv + установить зависимости + миграции |

|------------------------|----------------------------------------------------------|

| `make db-down`         | остановить контейнер (данные сохраняются)                |

| `make db-init`         | применить `01..04` SQL-скрипты                           |

| `make db-shell`        | открыть `psql` внутри контейнера                          |
| `make db-logs`         | следить за логами контейнера                              |
| `make status`          | статус контейнера и размеры таблиц                        |

## Конфигурация подключения

Файл `.env` создаётся автоматически из `.env.example` при первом
`make run`. Параметры по умолчанию:

```ini
PG_HOST=localhost
PG_PORT=5433       # 5433, чтобы не пересекаться с локальным postgres@5432
PG_DB=ac_oudo
PG_USER=postgres
PG_PASSWORD=postgres
```

Если у вас на 5432 ничего не висит — можно сменить `5433 → 5432` и в
`.env`, и в `docker-compose.yml`.

## Сборка РПЗ

Документ собирается из markdown через pandoc + кастомный `reference.docx`
со стилями ГОСТ 7.32-2017 (поля 30/15/20/20 мм, межстрочный 1.5,
Times New Roman 14 pt, заголовки UPPERCASE центрированные с новой
страницы).

```sh
make rpz       # пересобрать build/Воробьёв_РПЗ.docx
```

Цепочка: `make mermaid` → `make screenshots` → `make reference` →
`pandoc` → `tools/fixup_docx_tables.py` (постобработка таблиц:
авто-распределение ширин колонок, повтор заголовков, шрифт TNR 12 pt
в ячейках).

После открытия docx в Word нажмите **F9** на поле «СОДЕРЖАНИЕ» —
оглавление соберётся автоматически по всем заголовкам H1–H3.

## Что внутри приложения

**Три ролевые меню:**

- **Администратор** — 11 кнопок: 7 справочников (студенты, преподаватели,
  сотрудники, дисциплины, курсы, записи, договоры), 3 табличных отчёта
  и диалог «Аналитика (графики)».
- **Преподаватель** — 7 кнопок: задания, варианты, оценки, 3 отчёта
  по успеваемости и графическая аналитика.
- **Студент** — 3 отчёта в режиме «только чтение»: мои курсы, мои
  оценки, 100-балльная система.

**Особенности UI:**

- **Master-detail** в форме «Курсы»: при выборе курса автоматически
  обновляется подчинённая таблица «Задания курса».
- **Регистронезависимый поиск** по подстроке во всех CRUD-формах
  (использует функциональные индексы `LOWER(...)` в БД).
- **Графические отчёты** через Qt Charts: столбчатая «Средний балл по
  курсу (топ-12)», круговая «Распределение студентов по статусам».
- **Печатные карточки** одной сущности (например, «Карточка студента»)
  с реквизитами и подчинённой таблицей оценок.
- **Предпросмотр печати** через `QPrintPreviewDialog`, экспорт в PDF
  средствами Qt без дополнительных библиотек.
- **Транзакционность**: каждое CRUD-действие — отдельная транзакция
  с автоматическим откатом при ошибке.

**Архитектура** (см. `app/`):

```
app/views/        ← презентационный слой (Qt-виджеты)
    crud/         ← универсальный CrudView + 10 конкретных форм
    reports/      ← табличные + графические отчёты
app/services/     ← бизнес-логика (auth, reports)
app/db/           ← пул соединений + репозитории по таблицам
```

## Оптимизация запросов

Раздел §17 РПЗ опирается на реальный прогон `EXPLAIN ANALYZE` на
«продакшен-объёме» данных (≈ 2 000 студентов, 70 000 оценок).
Сценарий — регистронезависимый поиск студентов по подстроке ФИО:

```sql
SELECT id, full_name, status, enrollment_date
FROM   students
WHERE  LOWER(full_name) LIKE LOWER('Bulk-студент №15%')
ORDER  BY full_name;
```

| Метрика             | Без индекса | С функциональным индексом | Изменение |
|---------------------|-------------|---------------------------|-----------|
| Стоимость (cost)    | 50.46       | 27.20                     | −46 %     |
| Тип сканирования    | Seq Scan    | Index Scan                | —         |
| Прочитано буферов   | 20          | 4                         | −80 %     |
| Время выполнения    | 0.304 мс    | 0.078 мс                  | −74 %     |

Воспроизвести:

```sh
make db-reset             # чистая БД
make db-seed-bulk         # дозалить нагрузочный пакет
make db-explain-bulk      # снять EXPLAIN ANALYZE → build/explain_bulk_output.txt
```
