# АС ОУДО — Автоматизированная система ОУДО

Курсовая работа по дисциплине «Базы данных», МГТУ им. Н. Э. Баумана,
кафедра ИУ5. Перенос проекта из Microsoft Access на стек
**PostgreSQL 17 / Python 3.10+ / PyQt5**.

## Состав репозитория

```
ac_oudo/
├── app/                         исходный код приложения PyQt5
├── sql/                         DDL, индексы, представления, seed, EXPLAIN
├── docs/
│   ├── РПЗ.md  + 4 приложения   расчётно-пояснительная записка
│   ├── graphics/                8 диаграмм Mermaid (.mmd) + PNG
│   └── screenshots/             скриншоты UI (плейсхолдеры → реальные)
├── tests/test_smoke.py          чек-лист методики испытаний
├── tools/make_placeholders.py   генерация заглушек скриншотов
├── docker-compose.yml           PostgreSQL 17 в контейнере
├── Makefile                     управление БД, приложением, документами
├── requirements.txt             зависимости Python
├── .env.example                 шаблон конфигурации
└── build/                       результат сборки (РПЗ.docx, EXPLAIN-логи)
```

## Быстрый старт за один шаг

```sh
make demo
```

Эта цель:
1. поднимает PostgreSQL 17 в Docker и ждёт готовности;
2. создаёт `.venv`, ставит зависимости из `requirements.txt`;
3. применяет SQL-скрипты `01..04`;
4. запускает приложение АС ОУДО.

Окно «Авторизация» откроется через несколько секунд.

## Команды Makefile

```
make help                — список целей
make bootstrap           — db-up + venv + install + db-init
make demo                — bootstrap + run

make db-up               — поднять PostgreSQL в Docker
make db-down             — остановить контейнер (данные сохраняются)
make db-purge            — снести контейнер вместе с томом
make db-init             — применить SQL-скрипты схемы и сидов
make db-reset            — db-purge + db-up + db-init
make db-explain          — прогнать EXPLAIN ANALYZE до/после индексов
make db-shell            — открыть psql внутри контейнера
make db-logs             — следить за логами PostgreSQL
make status              — статус контейнера + размер таблиц

make venv                — создать .venv
make install             — установить зависимости в .venv
make run                 — запустить приложение
make smoke               — распечатать чек-лист методики испытаний

make mermaid             — собрать PNG из всех .mmd
make placeholders        — сгенерировать заглушки скриншотов
make rpz                 — собрать docs/build/Воробьёв_РПЗ.docx
make rpz-pdf             — собрать PDF (требует xelatex)

make clean               — удалить кэш Python и build/
make clean-all           — clean + .venv + Docker-том
```

## Конфигурация подключения

Файл `.env` (создаётся автоматически из `.env.example`):

```
PG_HOST=localhost
PG_PORT=5433       # 5433, чтобы не пересекаться с локальным postgres@5432
PG_DB=ac_oudo
PG_USER=postgres
PG_PASSWORD=postgres
```

Если у вас на 5432 ничего не висит, можно сменить `5433 → 5432` и в
`.env`, и в `docker-compose.yml`.

## Документация

- **`docs/РПЗ.md`** — основной текст РПЗ, 17 разделов: введение,
  предметная область, ограничения, документы, функциональная модель,
  DFD, IDEF0, ER, выбор СУБД, реляционная схема, схема работы,
  структурная схема, UI, граф диалога, **оптимизация запроса с
  реальными числами EXPLAIN**, заключение, литература.
- `docs/Приложение_А_ТЗ.md` — техническое задание по ГОСТ 19.201-78.
- `docs/Приложение_Б_Руководство_пользователя.md` — пошаговое руководство.
- `docs/Приложение_В_Методика_испытаний.md` — программа испытаний по
  ГОСТ 19.301-79 (28 пунктов).
- `docs/Приложение_Г_Графическая_часть.md` — 8 листов графики в виде PNG.
- `docs/graphics/*.mmd` — исходники Mermaid; `*.png` — собранные диаграммы.
- `build/Воробьёв_РПЗ.docx` — собранный сводный документ (`make rpz`).

### Замена заглушек на реальные скриншоты

`make placeholders` создаёт PNG-заглушки в `docs/screenshots/`. Каждая
заглушка подписана названием формы. После того как сделаете реальные
снимки приложения, **удалите заглушку и положите снимок с тем же именем**
(`01_login.png`, `13_teachers.png` и т. д.). Затем пересоберите docx:

```sh
make clean rpz
```

## Что осталось сделать вручную

1. **Снять реальные скриншоты** интерфейса (~25 штук) — pyqt-окно нельзя
   автоматизировать без виртуального дисплея. Сейчас в docx — заглушки
   с подписями.
2. **Проверить вывод EXPLAIN** — числа в §17 РПЗ записаны на основе
   фактического прогона на seed-данных. Если расширите датасет (например,
   увеличите grades до десятков тысяч строк), пересоберите docx.
3. **Подготовить титульный лист** в Word — `make rpz` собирает
   pandoc-style заголовок; для сдачи в БМСТУ-формате обычно требуется
   фирменный титульник, его проще сделать в Word поверх собранного docx.
