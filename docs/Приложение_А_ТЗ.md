# ПРИЛОЖЕНИЕ А — Техническое задание

**АИС ОУДО — автоматизированная информационная система образовательного
учреждения дистанционного обучения.** Техническое задание, оформлено
в соответствии с ГОСТ 19.201-78.

---

## А.1 Введение

### А.1.1 Наименование программы

Полное наименование: **«Автоматизированная информационная система
образовательного учреждения дистанционного обучения»**.
Краткое наименование: **АИС ОУДО**.

### А.1.2 Назначение и условия применения

АИС ОУДО предназначена для автоматизации управления учебной деятельностью
образовательного учреждения, ведущего обучение по программам
дистанционного образования. Применяется в учебной части и преподавательском
коллективе на персональных компьютерах под управлением Windows, macOS
или Linux.

### А.1.3 Основания для разработки

Курсовая работа по дисциплине «Базы данных» (кафедра ИУ5 МГТУ им. Н. Э.
Баумана). Основанием для разработки служит задание руководителя курсового
проекта.

## А.2 Требования к программе

### А.2.1 Требования к функциональным характеристикам

Программа должна обеспечивать выполнение следующих функций:

- регистрация и редактирование сведений о студентах, преподавателях,
  сотрудниках, дисциплинах, курсах;
- регистрация записи студентов на курс, ведение договоров об обучении и
  трудовых договоров;
- ведение перечня заданий и вариантов заданий с привязкой к курсу;
- выставление и редактирование оценок студентов по заданиям;
- разграничение доступа: административный, преподавательский,
  студенческий профили;
- формирование отчётов «Список курсов», «Сводка по записи»,
  «Преподаватели и курсы», «Средний балл по курсу», «100-балльная
  система», «Баллы студента», «Мои курсы»;
- формирование графических аналитических отчётов: столбчатая диаграмма
  «Средний балл по курсу (топ-12)» и круговая диаграмма «Распределение
  студентов по статусам» — средствами Qt Charts;
- формирование печатных карточек одной сущности (карточка студента) с
  подчинённой таблицей оценок;
- предпросмотр и печать любого отчёта в табличной форме, экспорт в PDF
  средствами Qt;
- поиск и фильтрация записей в каждой справочной форме (через
  регистронезависимое сравнение с использованием функциональных
  индексов `LOWER(...)`);
- master-detail-представление формы «Курсы»: подчинённая таблица
  «Задания курса» обновляется автоматически при выборе курса в основной
  таблице.

### А.2.1.1 Требования к входным данным

На вход системы поступают:

- учётные данные пользователей при входе (логин — VARCHAR(64), пароль —
  открытый текст, на стороне БД пересчитывается в bcrypt-хеш длиной 60–72
  байта);
- сведения о вновь зачисляемых студентах: ФИО, дата зачисления, статус
  обучения (значение типа `student_status`);
- сведения о принимаемых преподавателях: ФИО, должность, специализация;
- сведения о сотрудниках: ФИО, должность, уровень доступа (значение типа
  `access_level`);
- учебные планы — перечень дисциплин (название, число часов, описание);
- состав курсов на учебный год: название, дата начала, дата окончания,
  закреплённый преподаватель, дисциплина;
- заявки на запись на курс: пара «студент—курс», дата подачи;
- данные договоров: ссылка на сотрудника, ссылка на студента или
  преподавателя, тип договора (`contract_type`), дата заключения;
- учебные задания: название, описание, тип (`task_type`), срок, максимальный
  балл, привязка к курсу;
- варианты заданий: номер, описание;
- результаты проверки работ: ссылка на студента, ссылка на задание, балл
  (целое 0–100), дата выставления.

### А.2.1.2 Требования к выходным данным

Из системы формируются:

- табличные отчёты для печати: «Список курсов», «Сводка по записи»,
  «Преподаватели и курсы», «Средний балл по курсу», «100-балльная
  система», «Баллы студента», «Мои курсы»;
- графические отчёты средствами Qt Charts: столбчатая диаграмма топ-12
  курсов по среднему баллу; круговая диаграмма распределения студентов
  по статусам;
- печатная карточка одной сущности (карточка студента) с реквизитами и
  подчинённой таблицей оценок (источник — представление
  `v_student_grades`);
- системные сообщения об успехе/ошибке (`QMessageBox` соответствующих
  типов).

### А.2.2 Требования к надёжности

При сбое сетевого подключения или БД программа должна вывести
информационное сообщение и сохранить целостность данных. Транзакционность
изменений обеспечивается на уровне СУБД PostgreSQL: каждая операция
вставки/изменения/удаления выполняется внутри транзакции с автоматическим
откатом при ошибке.

### А.2.3 Условия эксплуатации

Программа эксплуатируется на персональных компьютерах в офисных условиях.
Климатические требования соответствуют ГОСТ 15150-69, климатическое
исполнение УХЛ4. Не требует специальных условий охраны труда.

### А.2.4 Требования к составу и параметрам технических средств

Минимальная конфигурация ПК:

- процессор класса Intel Core i3 или эквивалентный;
- ОЗУ — не менее 4 ГБ;
- не менее 200 МБ свободного места на диске для приложения и базовой
  СУБД;
- сетевое подключение для связи с сервером PostgreSQL (если БД
  развёрнута на отдельном узле).

### А.2.5 Требования к программной совместимости

- Операционная система: Windows 10/11, macOS 12+, Ubuntu 20.04+ /
  Debian 11+ (или совместимые дистрибутивы Linux);
- интерпретатор Python 3.10 и выше;
- СУБД PostgreSQL 17 (минимально совместимая — 13) с расширением
  `pgcrypto`; рекомендуется развёртывание через Docker по образу
  `postgres:17-alpine`;
- Python-библиотеки: PyQt5 ≥ 5.15.11, PyQtChart ≥ 5.15.7,
  psycopg2-binary ≥ 2.9.10, bcrypt ≥ 4.2.0, python-dotenv ≥ 1.0.1,
  reportlab ≥ 4.2.5. Полный перечень — в файле `requirements.txt`.

### А.2.6 Требования к информационной совместимости

Структура БД должна соответствовать схеме, описанной в `sql/01_schema.sql`.
Кодировка хранения и обмена — UTF-8.

## А.3 Требования к программной документации

В состав документации входит:

- настоящее техническое задание (Приложение А);
