# ПРИЛОЖЕНИЕ В — Программа и методика испытаний

Документ оформлен в соответствии с ГОСТ 19.301-79.

## В.1 Объект испытаний

Объектом испытаний является **АС ОУДО** — настольное приложение,
реализованное на Python 3.10+ с использованием фреймворка PyQt5 и
модуля Qt Charts (через PyQtChart), работающее с СУБД PostgreSQL 17.

## В.2 Цель испытаний

Подтвердить соответствие реализации функциональным требованиям ТЗ
(Приложение А, п. А.2.1) и проверить устойчивость к типовым ошибочным
действиям пользователя, в том числе на «продакшен-объёмах» данных
(см. сценарий из §17 РПЗ и `sql/06_seed_bulk.sql`).

## В.3 Состав предъявляемой документации

- РПЗ (`docs/РПЗ.md`);
- ТЗ (Приложение А);
- Руководство пользователя (Приложение Б);
- Графическая часть из 8 листов (Приложение Г);
- Исходные тексты в каталоге `app/` и `sql/`.

## В.4 Условия проведения испытаний

- Стенд: ноутбук Apple MacBook (macOS 14, arch arm64, Python 3.12,
  PostgreSQL 17 в Docker);
- БД заполнена скриптами из каталога `sql/`;
- Установлены зависимости из `requirements.txt`.

## В.5 Порядок проведения испытаний

Перед каждой группой проверок БД заново инициализируется командой:

```sh
make db-reset
```

(внутри Makefile это последовательность `db-purge → db-up → db-init`,
которая применяет `01_schema.sql`, `02_indexes.sql`, `03_views.sql`,
`04_seed.sql`). Для проверок раздела В.6.7 «Производительность» дополнительно
выполняется:

```sh
make db-seed-bulk    # дозалить 06_seed_bulk.sql
make db-explain-bulk # снять EXPLAIN ANALYZE на больших объёмах
```

Затем из корня проекта запускается приложение:

```sh
make run
```

## В.7 Критерии приёмки

Система признаётся прошедшей испытания, если:

- все тесты разделов В.6.1–В.6.8 пройдены без ошибок;
- ни один из выводов на печать (отчёт, карточка) не содержит пустых
  обязательных полей или некорректного форматирования;
- при отключении сервера PostgreSQL приложение не «падает», а
  показывает понятное сообщение об ошибке (см. также автоматический
  smoke-тест `tests/test_smoke.py`).
